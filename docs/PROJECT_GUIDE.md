# Полная инструкция по проекту «Дурак только на Oracle»

## 1. Что это за проект

Проект реализует серверную карточную игру «Дурак» только средствами Oracle
Database. Внешнее приложение и графический интерфейс не требуются: игроки
подключаются через SQL Developer, SQLcl или SQL*Plus, выполняют команды PL/SQL
и читают состояние из представлений.

Основная редакция содержит требования минимального и хорошего уровней:

- от 2 до 6 игроков;
- колоды 36 и 52 карты;
- подкидной и переводной варианты;
- первый ход по младшему козырю или детерминированно по seed;
- атака, защита, подбрасывание, перевод, пас и взятие;
- добор до шести карт, выход игроков и определение дурака;
- таймеры хода и завершение простаивающих партий;
- маскирование чужих карт;
- Daily, реплей, журнал и табло результатов.

Ботов, турниров, расширенной аналитики и настраиваемых домашних правил в
основной установке нет.

## 2. Как устроена система

Работа одной команды проходит по следующей цепочке:

```text
SQL Developer
    -> DURAK_CONSOLE или DURAK_API
    -> DURAK_ENGINE
    -> DURAK_RULES и DURAK_RANDOM
    -> таблицы Oracle
    -> защищённые представления
```

- `DURAK_CONSOLE` принимает короткие русские команды.
- `DURAK_API` определяет игрока по `SESSION_USER`, проверяет доступ и возвращает
  сообщения `УСПЕШНО` или `ОТКАЗ`.
- `DURAK_ENGINE` блокирует строку партии и атомарно изменяет состояние игры.
- `DURAK_RULES` проверяет бой карт и лимиты стола.
- `DURAK_RANDOM` строит воспроизводимый порядок колоды по seed.
- `DURAK_MAINTENANCE` и `DBMS_SCHEDULER` обрабатывают таймеры.
- представления показывают только разрешённую текущему пользователю информацию.

Карты не копируются между таблицами. Каждый экземпляр карты партии находится в
одной зоне: `TALON`, `HAND`, `TABLE` или `DISCARD`. Полный протокол записывается
в `DURAK_EVENT`, а перемещения карт — в `DURAK_CARD_MOVE`.

## 4. Быстрый запуск Oracle в Docker

Если Oracle уже установлен, этот раздел можно пропустить.

Создайте контейнер, заменив пароли своими значениями:

```bash
docker run -d \
  --name durak-oracle \
  -p 1521:1521 \
  -e ORACLE_PASSWORD='<пароль_SYS>' \
  -e APP_USER=DURAK_OWNER \
  -e APP_USER_PASSWORD='<пароль_DURAK_OWNER>' \
  -v durak-oracle-data:/opt/oracle/oradata \
  gvenzl/oracle-free:latest
```

Проверьте запуск:

```bash
docker logs -f durak-oracle
```

Продолжайте после сообщения `DATABASE IS READY TO USE!`. В дальнейшем контейнер
запускается командой:

```bash
docker start durak-oracle
```

Пароли не следует записывать в файлы проекта или добавлять в Git.

## 5. Подключение SQL Developer

Для владельца игры создайте подключение со следующими параметрами:

| Поле | Значение для Docker |
|---|---|
| Name | `durak-owner` |
| Username | `DURAK_OWNER` |
| Password | пароль из `APP_USER_PASSWORD` |
| Connection Type | `Basic` |
| Hostname | `localhost` |
| Port | `1521` |
| Тип адреса | `Service name` |
| Service name | `FREEPDB1` |
| Role | `default` |

Нажмите `Test`, затем `Connect`. Если соединение не устанавливается:

1. убедитесь, что контейнер запущен: `docker ps`;
2. дождитесь полной готовности базы в `docker logs durak-oracle`;
3. используйте `Service name = FREEPDB1`, а не `SID = xe`;
4. проверьте, что порт `1521` не занят другим Oracle;
5. не подключайтесь к службе `FREE`, потому что пользователь приложения создан
   в подключаемой базе `FREEPDB1`.

## 6. Установка игры

Откройте подключение `DURAK_OWNER`, затем откройте файл `install.sql` из корня
проекта и выполните его как сценарий клавишей `F5`.

```sql
@install.sql
```

Установка должна завершиться без ошибок компиляции. Для проверки объектов:

```sql
SELECT object_name, object_type, status
FROM user_objects
WHERE object_type IN ('PACKAGE', 'PACKAGE BODY', 'VIEW')
  AND status <> 'VALID'
ORDER BY object_type, object_name;
```

Ожидается `no rows selected`.

Повторная установка удаляет игровые данные:

```sql
@reinstall.sql
```

Поэтому `reinstall.sql` следует запускать только перед чистой демонстрацией или
если старая схема больше не нужна.

## 7. Создание пользователей игроков

Каждый человек должен играть из отдельного Oracle-пользователя. Подключитесь к
`FREEPDB1` пользователем `SYSTEM` или `SYS` и создайте, например, двух игроков:

```sql
CREATE USER PLAYER_ONE IDENTIFIED BY "<пароль_игрока_1>";
GRANT CREATE SESSION TO PLAYER_ONE;

CREATE USER PLAYER_TWO IDENTIFIED BY "<пароль_игрока_2>";
GRANT CREATE SESSION TO PLAYER_TWO;
```

Для партии на 3–6 человек аналогично создайте `PLAYER_THREE` и остальных.

Вернитесь в подключение `DURAK_OWNER` и выдайте каждому только разрешённые
права:

```sql
@admin/grant_player_access.sql PLAYER_ONE
@admin/grant_player_access.sql PLAYER_TWO
```

Сценарий выдаёт право выполнять `DURAK_API`, `DURAK_CONSOLE` и читать
защищённые представления. Прямого доступа к игровым таблицам и движку у игроков
нет.

Создайте в SQL Developer отдельное подключение для каждого пользователя:

- `player-one`: пользователь `PLAYER_ONE`;
- `player-two`: пользователь `PLAYER_TWO`;
- те же `localhost`, `1521` и `FREEPDB1`.

## 8. Создание обычной партии

В окне `PLAYER_ONE` выполните:

```sql
@demo/01_creator.sql DURAK_OWNER Михаил demo-seed-1
```

Сценарий:

1. регистрирует текущего Oracle-пользователя как игрока;
2. создаёт подкидную партию на 36 карт;
3. выводит `PLAYER_ID`, `GAME_ID` и текст результата.

Запишите `GAME_ID`. Например, если получено `2102`, во втором окне выполните:

```sql
@demo/02_joiner.sql DURAK_OWNER Анна 2102
```

Для 3–6 игроков каждый следующий пользователь выполняет тот же сценарий со
своим именем и тем же `GAME_ID`.

После подключения всех участников создатель выполняет:

```sql
@demo/03_start.sql DURAK_OWNER 2102
```

Движок создаст колоду, раздаст каждому по шесть карт, откроет козырь и определит
первого атакующего.

## 9. Просмотр состояния игры

В каждом окне игрока один раз переключите текущую схему:

```sql
ALTER SESSION SET CURRENT_SCHEMA = DURAK_OWNER;
```

Затем состояние можно смотреть одним запросом:

```sql
SELECT game_text,
       turn_text,
       hand_text,
       table_text,
       players_text,
       command_hint,
       last_event_text
FROM v_game_console
WHERE game_id = 2102;
```

`HAND_TEXT` для каждого подключения будет разным: игрок видит только свою руку.
Чужие карты показываются количеством.

Подробные представления:

```sql
SELECT * FROM v_game_status WHERE game_id = 2102 ORDER BY seat_no;
SELECT * FROM v_hand_mine WHERE game_id = 2102 ORDER BY rank_value, suit_code;
SELECT * FROM v_hand_public WHERE game_id = 2102 ORDER BY seat_no;
SELECT * FROM v_table WHERE game_id = 2102 ORDER BY pair_no;
```

Поле `MY_ALLOWED_ACTIONS` в `V_GAME_STATUS` и подсказка `COMMAND_HINT` в
`V_GAME_CONSOLE` сообщают, что текущему игроку разрешено сделать сейчас.

## 10. Как выполнять ходы

В каждом окне один раз создайте переменную для ответа:

```sql
VARIABLE message VARCHAR2(1000)
```

Доступные команды:

```sql
EXEC durak_console.play('ХОД 8H', :message)
EXEC durak_console.play('БИТО 9H 1', :message)
EXEC durak_console.play('ПОДКИНУТЬ 8C', :message)
EXEC durak_console.play('ПЕРЕВОД 8D', :message)
EXEC durak_console.play('ВЗЯТЬ', :message)
EXEC durak_console.play('ПАС', :message)
PRINT message
```

Коды мастей:

- `C` — трефы;
- `D` — бубны;
- `H` — червы;
- `S` — пики.

Примеры кодов карт: `6C`, `10H`, `QD`, `AS`.

Можно передать только карту:

```sql
EXEC durak_console.play('8H', :message)
PRINT message
```

Консоль сама выберет атаку, защиту или подбрасывание по текущей фазе. Для
защиты нескольких пар лучше явно указывать номер пары: `БИТО 9H 2`.

Справка:

```sql
EXEC durak_console.help(:message)
PRINT message
```

После каждой команды снова запрашивайте `V_GAME_CONSOLE`. Если команда
недопустима, данные не изменятся, а в `MESSAGE` будет указана причина отказа.

## 11. Правила хода

1. Атакующий кладёт первую карту.
2. Защитник бьёт её старшей картой той же масти либо козырем.
3. Козырь можно побить только старшим козырем.
4. После покрытия атакующая сторона может подбрасывать только достоинства,
   которые уже лежат на столе.
5. Число пар ограничено параметром `MAX_PAIRS` и исходным числом карт защитника.
6. Если все атакующие карты покрыты и атакующие пасуют, стол уходит в отбой.
7. Если защитник выбирает `ВЗЯТЬ`, карты стола переходят в его руку.
8. После раунда сначала добирает атакующая сторона, затем защитник.
9. Когда талон пуст, игрок с пустой рукой выходит и пропускается в дальнейшем.
10. Последний игрок с картами становится дураком.

В переводном варианте защитник до первой защиты может выполнить `ПЕРЕВОД`
картой того же достоинства. Следующий активный игрок становится защитником.

## 12. Создание партии с другими параметрами

Пример партии на 52 карты в переводном режиме со случайным первым ходом по seed:

```sql
VARIABLE game_id NUMBER
VARIABLE message VARCHAR2(1000)

BEGIN
  durak_api.create_game(
    p_game_id          => :game_id,
    p_message          => :message,
    p_deck_size        => 52,
    p_game_variant     => 'PEREVODNOY',
    p_first_move_mode  => 'SEEDED_RANDOM',
    p_turn_timeout_sec => 60,
    p_idle_timeout_min => 30,
    p_seed_text        => 'demo-seed-52'
  );
END;
/

PRINT game_id
PRINT message
```

Допустимые значения:

| Параметр | Значения |
|---|---|
| `P_DECK_SIZE` | `36` или `52` |
| `P_GAME_VARIANT` | `PODKIDNOY` или `PEREVODNOY` |
| `P_FIRST_MOVE_MODE` | `LOWEST_TRUMP` или `SEEDED_RANDOM` |
| `P_MAX_PAIRS` | по умолчанию 6 для 36 и 8 для 52 |
| `P_TURN_TIMEOUT_SEC` | `0` отключает таймер хода |
| `P_IDLE_TIMEOUT_MIN` | время завершения простаивающей партии |

При одинаковых параметрах и seed порядок карт будет одинаковым.

## 13. Таймеры

Фоновое задание проверяется запросом:

```sql
SELECT job_name, enabled, state
FROM user_scheduler_jobs
WHERE job_name = 'DURAK_MAINTENANCE_JOB';
```

Ожидается `ENABLED = TRUE`. После истечения времени:

- в ожидании первой атаки движок выбирает допустимую карту;
- защитник автоматически берёт карты;
- подбрасывающий автоматически пасует;
- длительно простаивающая партия получает статус `EXPIRED`.

Причина и источник `TIMEOUT` сохраняются в протоколе.

## 14. Журнал и реплей

Читаемый журнал:

```sql
SELECT log_line
FROM v_log_text
WHERE game_id = 2102
ORDER BY event_no;
```

Подробный реплей:

```sql
SELECT replay_step_no,
       event_no,
       event_type,
       actor_name,
       event_card_code,
       moved_card_code,
       from_zone,
       to_zone,
       phase_before,
       phase_after,
       event_message
FROM v_replay
WHERE game_id = 2102
ORDER BY replay_step_no;
```

Во время активной партии закрытые события другого игрока маскируются. После
завершения участникам доступна полная история.

## 15. Daily

Создание партии с раскладкой на определённую дату:

```sql
@demo/05_daily.sql DURAK_OWNER Михаил 2026-09-24
```

Другие игроки присоединяются через `demo/02_joiner.sql`. Одинаковые дата,
версия правил и параметры создают одинаковый Daily seed.

Просмотр раскладки дня:

```sql
SELECT *
FROM v_daily
ORDER BY daily_date DESC, daily_id DESC;
```

Результаты дня:

```sql
SELECT *
FROM v_daily_results
WHERE daily_id = <DAILY_ID>
ORDER BY daily_place, finish_place;
```

В подключении `DURAK_OWNER` выполните:

```sql
SET SERVEROUTPUT ON SIZE UNLIMITED

```

Ожидаемый итог:

```text

```

Проверяются карты, правила боя, seed, маскирование данных, объекты схемы,
полный раунд, взятие, добор, таймеры, Daily, 2–6 игроков, колода 52, перевод и

## 18. Частые сообщения

### «У игрока нет карты 10C»

Запрошенной карты нет в вашей руке. Посмотрите `HAND_TEXT` или `V_HAND_MINE` и
используйте один из показанных кодов.

### «Сейчас нельзя начинать атаку»

Сейчас ход другого игрока или игра находится в фазе защиты/подбрасывания.
Проверьте `TURN_TEXT`, `COMMAND_HINT` и `MY_ALLOWED_ACTIONS`.

### «У пользователя нет активной партии»

Пользователь не создал и не подключился к партии либо партия завершена.
Подключитесь через `JOIN_GAME` или вызовите перегрузку консоли с `GAME_ID`:

```sql
EXEC durak_console.play(2102, 'ХОД 8H', :message)
```

### «Игрок уже участвует в активной партии»

По заданию один Oracle-пользователь может иметь только одну активную игровую
сессию. Завершите или отмените предыдущую партию.

### `ORA-20702`

Другая сессия сейчас изменяет ту же партию. Обновите состояние и повторите
команду после освобождения блокировки.

### Файл запускается как один оператор и появляются ошибки на `/`

SQL-файлы необходимо выполнять как сценарий клавишей `F5`, а не как отдельный
оператор `Ctrl+Enter`.

## 19. Порядок функциональной проверки

1. Показать отсутствие невалидных объектов.
